================================================================================
DOCUMENTAÇÃO TÉCNICA DE INTEGRAÇÃO - MERCADO PAGO (PAGAMENTO COM CARTÃO DE CRÉDITO)
AURA REGENERA / SITE-PEP
================================================================================

Este documento descreve detalhadamente todos os dados que são capturados, processados
e enviados para as APIs do Mercado Pago durante a finalização de uma compra via
Cartão de Crédito no checkout da plataforma.

--------------------------------------------------------------------------------
1. RESUMO DO FLUXO DE PAGAMENTO COM CARTÃO DE CRÉDITO
--------------------------------------------------------------------------------

O processamento de cartão ocorre em 2 etapas distintas de API por motivos de segurança e compliance PCI-DSS:

1. ETAPA 1 (Tokenização do Cartão - Frontend -> API Mercado Pago):
   Os dados brutos do cartão (número, código de segurança, validade e nome) são enviados
   diretamente para a API de Card Tokens do Mercado Pago (`/v1/card_tokens`) usando a Chave Pública
   (NEXT_PUBLIC_MERCADO_PAGO_PUBLIC_KEY). Em resposta, o Mercado Pago retorna um token criptografado
   único e temporário (ex: `c7a8b9e0f1...`), evitando que dados sensíveis de cartão fiquem
   salvos no servidor da aplicação.

2. ETAPA 2 (Cobrança do Pagamento - Server-side / API Next.js -> API Mercado Pago):
   No arquivo `src/app/api/payment/process/route.ts`, o servidor recebe o token e monta o payload completo
   contendo o valor da transação, o token do cartão, parcelamento, identificador da sessão antifraude (Device ID),
   dados cadastrais do comprador (Payer), resumo dos itens do carrinho e endereço completo de entrega.
   Esse payload é enviado via requisição segura POST para `/v1/payments` utilizando o Token de Acesso Privado
   (MERCADO_PAGO_ACCESS_TOKEN).

3. MAPEAMENTO DETALHADO: ONDE E COMO CADA DADO É OBTIDO
--------------------------------------------------------------------------------

1. DADOS DO CARTÃO DE CRÉDITO
   - Onde são obtidos: Formulário de Pagamento no checkout (`src/app/checkout/page.tsx`, linhas 893-988).
   - Como são obtidos: Digitados manualmente pelo usuário no Passo 2 do Checkout nos campos de input.
   - Campos:
     * `card_number`: Input "Número do Cartão" -> sanitizado removendo caracteres não numéricos.
     * `expiration_month` / `expiration_year`: Input "Validade (MM/AA)" -> dividido pela barra ("/").
     * `security_code`: Input "Código CVV" -> sanitizado (3 a 4 dígitos).
     * `cardholder.name`: Input "Nome Impresso no Cartão" -> convertido para maiúsculas (`.toUpperCase()`).
     * `cardholder.identification.number`: Input "CPF do Titular" -> sanitizado removendo pontuações.

2. PARCELAMENTO (INSTALLMENTS)
   - Onde é obtido: Menu Select de parcelas no checkout (`src/app/checkout/page.tsx`, linhas 975-986).
   - Como é obtido: Selecionado pelo cliente (de 1x até 10x). O sistema calcula os juros com base na tabela `MP_INSTALLMENT_FACTORS`.

3. BANDEIRA E BANCO EMISSOR (PAYMENT_METHOD_ID & ISSUER_ID)
   - Onde são obtidos: Resolução automática no servidor (`src/app/api/payment/process/route.ts`, linhas 41-68 e 293-330).
   - Como são obtidos:
     * `payment_method_id`: Identificado dinamicamente a partir dos 6 primeiros dígitos do cartão (BIN) através da função `detectCardBrand()` (suporta Elo, Hipercard, Visa, Mastercard, Amex) ou retornado diretamente pelo Token do Mercado Pago.
     * `issuer_id`: Obtido fazendo uma chamada em tempo real para a API do Mercado Pago (`https://api.mercadopago.com/v1/payment_methods/card_issuers`) informando a bandeira e os 6 primeiros dígitos do cartão (BIN).

4. DADOS DO COMPRADOR / COMPRADORA (PAYER)
   - Onde são obtidos: Sessão do usuário autenticado via `AuthContext` (`src/context/AuthContext.tsx`), armazenada no banco de dados / localStorage.
   - Como são obtidos: Preenchidos automaticamente a partir do cadastro do profissional/cliente na plataforma Aura Regenera.
   - Campos:
     * `email`: E-mail cadastrado na conta (`user.email`).
     * `first_name` / `last_name`: Nome e Sobrenome divididos a partir do cadastro (`user.firstName`, `user.lastName`).
     * `identification.number`: CPF ou CNPJ cadastrado (`user.cpfCnpj`).
     * `phone`: Telefone/WhatsApp cadastrado (`user.phone`), separado em código de área (DDD - 2 dígitos) e número (8 ou 9 dígitos).

5. ENDEREÇO DE ENTREGA (SHIPMENTS & METADATA)
   - Onde é obtido: Lista de endereços cadastrados na conta (`user.addresses`), selecionado pelo usuário no Passo 1 do Checkout (`src/app/checkout/page.tsx`, linhas 683-734).
   - Como é obtido: Objeto `selectedAddress` contendo logradouro (`street`), número (`number`), complemento (`complement`), bairro (`neighborhood`), cidade (`city`), estado (`state`) e CEP (`cep`).

6. RESUMO E ITENS DO PEDIDO (ITEMS & TRANSACTION_AMOUNT)
   - Onde são obtidos: Estado global do Carrinho (`CartContext` em `src/context/CartContext.tsx`).
   - Como são obtidos:
     * `items`: Array de produtos no carrinho, contendo ID, nome do protocolo/produto (`name`), quantidade (`quantity`) e preço unitário (`unitPrice`).
     * `transaction_amount`: Valor total da compra (`subtotal + shippingCost`).

7. DISPOSITIVO E ANTIFRAUDE (DEVICE ID / X-MELI-SESSION-ID)
   - Onde é obtido: Script oficial de segurança do Mercado Pago (`https://www.mercadopago.com/v2/security.js`) carregado no arquivo `src/app/checkout/page.tsx` (linhas 1016-1021).
   - Como é obtido: O script gera uma impressão digital única do dispositivo/navegador (Session ID), armazenada no elemento DOM `<input type="hidden" id="deviceId" />` ou na variável `window.MP_DEVICE_SESSION_ID`, e enviada no cabeçalho HTTP `X-Meli-Session-Id` ao Mercado Pago para análise de risco antifraude.

--------------------------------------------------------------------------------
4. CONFIGURAÇÕES DE SEGURANÇA E AMBIENTE
--------------------------------------------------------------------------------

- `NEXT_PUBLIC_MERCADO_PAGO_PUBLIC_KEY`: Chave pública usada no frontend para tokenizar cartões de crédito com segurança sem expor credenciais privadas.
- `MERCADO_PAGO_ACCESS_TOKEN`: Token de acesso privado usado exclusivamente no servidor Next.js (`src/app/api/payment/process/route.ts`) para autorizar a cobrança final na API do Mercado Pago.
- `binary_mode: true`: Garante que a resposta da transação seja imediata (aprovada ou recusada), sem passar por estados intermediários de pendência manual.
